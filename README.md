# Academic homepage

A minimal, fast academic website in the spirit of Kyle Ormsby's
[e-infinity.space](https://e-infinity.space): warm **paper & ink** palette
declared as light/dark pairs, one serif for everything + one mono for
labels, gradient-underline links, a rule that trails off after each
section label, a no-flash dark-mode toggle, and build-time-free KaTeX math.

Everything is generated by a small dependency-free Python script — no
framework, no npm, no `node_modules`. Just `python3`.

## Files

```
.
├── style.md         # ← DESIGN: colours, fonts, spacing (light/dark pairs)
├── content.md       # ← WORDS: your identity, nav, footer, sections
├── base.css         # structural rules (labels, links, layout) — rarely edited
├── build.py         # markdown + style.md → HTML/CSS (stdlib only)
├── serve.py         # live-preview server: rebuild + reload on save
├── template.html    # page skeleton (head, nav, footer, theme script)
├── font-lab.html    # DEV TOOL: cycle through fonts on the live site
├── vendor_font.py   # self-host any Google font (keeps the chosen one)
│
├── index.html       # GENERATED — do not edit by hand
├── styles.css       # GENERATED from style.md + base.css
│
├── fonts/           # self-hosted woff2 + fonts.css (no third-party requests)
├── vendor/katex/    # vendored KaTeX (CSS, JS, fonts) for math
├── media/           # your images, diagrams, headshot
├── viz/             # your interactive HTML/JS/WebGL animations
├── pages/           # optional extra pages, one .md each → <name>.html
├── files/           # cv.pdf, slides, etc.
└── favicon.svg
```

The three files you actually edit are **`style.md`** (the look),
**`content.md`** (the words), and occasionally **`base.css`** (structure).

## Live preview (the editing workflow)

```bash
python3 serve.py
```

Opens the site and watches `content.md`, `style.md`, `base.css`,
`pages/*.md`, `template.html`, and `build.py`. Save any of them and the
browser reloads. Build errors show as a red overlay instead of a stale
page. Edit markdown on one half of the screen, watch the site update on
the other.

Or build once and serve statically:

```bash
python3 build.py && python3 -m http.server
```

## style.md — the design system

All colour, type, spacing, and width choices live in the frontmatter of
`style.md` as `key: value` lines. `build.py` turns each into a CSS custom
property in `styles.css`. **This is where you reskin the site.**

- A key ending in **`-light` / `-dark`** is a *theme pair*: `accent-light`
  and `accent-dark` both become `--accent`, using the light value by
  default and the dark value under the toggle. The whole palette is pairs.
- Any other key is a single value used in both themes (`font-serif`,
  `measure`, the `s1…s9` spacing scale, etc.).
- Lines starting with `#`, and any prose, are ignored — comment freely.

The seeded palette is Kyle's warm paper/ink with a terracotta accent.
Change the fourteen colour values to make it yours; resist adding an
eighth colour.

## content.md — the words

Starts with a frontmatter block:

| key           | what it is                                             |
|---------------|--------------------------------------------------------|
| `name`        | your name (the h1 and the nav brand)                   |
| `subtitle`    | the line under your name                               |
| `contact`     | parts separated by `\|` become separate lines          |
| `description` | the page's meta description (for search/social)        |
| `nav`         | top nav: `\|`-separated `Label target` (see below)      |
| `footer`      | `\|`-separated parts, shown as mono labels             |

**Nav** items are `Label target` pairs. A target is a `#anchor` (a section
id, auto-slugified from its heading — `## About me` → `#about-me`) or a
path (`files/cv.pdf`, `teaching.html`). Example:

```
nav: research #about-me | preprints #preprints | cv files/cv.pdf
```

After the frontmatter, every `## Heading` starts a section (rendered as a
label with a rule trailing off). Sections appear in file order. Link a
heading — `## [Teaching](teaching.html)` — to make it clickable.

**Prose sections** take markdown: paragraphs, `**bold**`, `*italics*`,
`[links](url)`, `- lists`, `> quotes`, `###` subheadings, `` `code` ``,
`![images](media/x.png)`, and raw HTML (passed through untouched).

**Entry-list sections** (publications, talks) put `<!-- entries -->` after
the heading, then `key: value` blocks separated by `---`:

```markdown
## Preprints
<!-- entries -->

title: Title of the paper
authors: **Your Name**, Coauthor
year: 2025
status: Submitted
arxiv: https://arxiv.org/abs/0000.00000
```

Recognized keys: `title` (required), `authors` (bold your name with
`**…**`), `year`, `status`, link keys `arxiv`/`doi`/`pdf`, and a freeform
`links:` for extra markdown links.

## Math

Write TeX inline with `$…$` and display with `$$…$$`:

```markdown
The class $\pi_*^s$ and its filtration
$$E_2^{s,t} \Rightarrow \pi_{t-s}.$$
```

`build.py` shields math from the markdown pass (so `_` and `*` inside a
formula aren't mangled) and renders it in the browser with **vendored
KaTeX** — the KaTeX assets are included only on pages that actually
contain math, and are served from `vendor/katex/`, so no request ever
leaves your visitors' machines.

## Graphics, animations, and a photo

- **Images:** `![alt](media/chart.png)` anywhere in a section. For a
  caption, use raw HTML `<figure>…<figcaption>` (it passes through).
- **A headshot** that floats beside your intro:
  `<img class="portrait" src="media/me.jpg" alt="Your Name">`.
- **Interactive HTML animations** you generate from your mathematics: drop
  a self-contained page in `viz/` and embed it with
  `<iframe class="viz" src="viz/thing.html" title="…" loading="lazy">`.
  Add `class="viz bleed"` to break out wider than the text column.

See `media/README.md` and `viz/README.md` for details. Keep animations
self-contained (vendor any JS locally) to preserve the zero-third-party
property.

## Dark mode

Light is the default; dark is behind the nav toggle. The choice is saved
in `localStorage` and applied *before first paint* by a tiny inline script,
so dark-mode visitors never see a flash of light. The toggle ships hidden
and is un-hidden by JS, so no-JS visitors never see a dead control. Define
both palettes via the `-light`/`-dark` pairs in `style.md`.

## Fonts — browsing, choosing, self-hosting

The site ships with **Newsreader** (serif, everything) and **IBM Plex
Mono** (labels), self-hosted in `fonts/` — no Google Fonts request.

**To try other fonts**, run `python3 serve.py` and open
<http://localhost:8000/font-lab.html>. Cycle a big curated list with the
arrow keys and watch each one on your *actual* live page; switch between
the serif slot (body + headings) and the mono slot (labels); toggle dark.
It shows the exact `style.md` lines for your current pick. (Font Lab
previews from Google Fonts — it's a dev tool, not the published site.)

**To keep the one you chose**, self-host it so the public site stays
request-free:

```bash
python3 vendor_font.py "Fraunces" "JetBrains Mono"
```

That downloads the woff2 files into `fonts/` and appends the `@font-face`
rules to `fonts/fonts.css`. Then set `font-serif:` / `font-mono:` in
`style.md` and run `python3 build.py`.

## Extra pages

Drop a markdown file in `pages/` and it becomes a standalone page with the
same shell: `pages/teaching.md` → `teaching.html`. Page frontmatter takes
optional `title:` and `description:`; the body uses the same section rules.
Each page gets the site nav and a back-link home. Wire it into the homepage
by linking a section heading or a nav item to it.

## Publishing on GitHub Pages

The generated `.html`/`.css` are committed, so Pages needs no build step —
just run `python3 build.py` before committing content changes.

1. Push to `main`.
2. **Settings → Pages** → Source = "Deploy from a branch", Branch =
   `main`, folder = `/ (root)`.
3. Live at `https://<username>.github.io/` in a minute or two.

All asset paths are relative, so it also works as a project site under
`/<repo-name>/`. Note that GitHub Pages can't set response headers (no
CSP); the site's security posture is instead its *tiny attack surface* —
fully static, no analytics, no cookies beyond the one `theme` key, and
zero third-party requests. For real headers, host the same output on
Cloudflare Pages or Netlify.
