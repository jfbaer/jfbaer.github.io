# Deploying to GitHub Pages

The site is a plain static build (`python3 build.py` writes the `.html` +
`styles.css`; everything else is committed as-is). GitHub Pages just serves the
repo, so hosting is: push the repo, flip Pages on.

## Current state: PUBLIC (since 2026-09-21)

The site is live at **https://jfbaer.github.io** (user site: this repo pushes
to `jfbaer/jfbaer.github.io`, Pages deploys `main` / root) and is **open to
search engines**:

- no robots `<meta>` tag anywhere (`template.html` used to emit
  `noindex, nofollow`; it's gone).
- `robots.txt` allows all crawlers and points to `sitemap.xml`.
- `sitemap.xml` lists the five pages (index, research, teaching, fun,
  steenrod-modules).

To help/monitor indexing: verify the site in Google Search Console, submit
`sitemap.xml`, and use "Request indexing" on the homepage.

## Re-unlisting (if the site ever needs to go dark again)

1. Add `<meta name="robots" content="noindex, nofollow">` to the `<head>` of
   `template.html` **and** of `steenrod-modules.html` — that page is
   standalone, not generated by `build.py`, and is easy to miss.
2. In `robots.txt`, replace the empty `Disallow:` with `Disallow: /`.
3. `python3 build.py` to rebuild the pages, then commit and push.

Note this only stops *new* indexing; already-indexed pages linger in Google
for a while (use Search Console's removal tool to expedite). And free GitHub
Pages has **no password protection** — anyone with the link can view. (For a
true login wall you'd need a paid host like Netlify/Cloudflare Access.)

> The repo must be **public** for Pages on a free account (a public repo is
> fine — it's a static site). Publishing from a *private* repo needs GitHub Pro.

## Everyday updates

```sh
python3 build.py     # regenerate html/css from style.md, content.md, pages/*
git add -A && git commit -m "..." && git push
```

Pages redeploys automatically on push.
